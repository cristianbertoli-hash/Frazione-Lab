# FRA1-QR v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a web-first FRA1-QR v0 prototype that encrypts files up to 100 KiB as FRA1E AES-256, splits the ciphertext into ordered QR transport frames, animates standard black/white QR codes, and deterministically reconstructs and decrypts the original file byte-for-byte.

**Architecture:** Keep cryptography unchanged in `codec.js`. Add a focused `fra1qr.js` transport module for framing, CRC32, splitting, Base64URL QR text encoding, validation, and reassembly. Extend the existing static web UI in `index.html`/`app.js` with an experimental FRA1-QR card. QR rendering uses a pinned browser QR renderer; camera scanning is explicitly deferred.

**Tech Stack:** Vanilla JavaScript, Web Crypto, existing FRA1/FRA1E codec, Node.js tests, standard QR Code Model 2 via pinned QRCode.js renderer, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-06-fra1-qr-v0-design.md`

## Global Constraints

- Input file limit for FRA1-QR v0: `100 * 1024` bytes.
- Cryptographic payload must be FRA1E AES-GCM 256-bit produced by the existing codec.
- Password derivation remains PBKDF2-HMAC-SHA256 with 600,000 iterations and random salt/IV.
- QR symbols remain standard black/white; no grayscale or color encoding in v0.
- Live camera scanning is not part of v0.
- QR transport must not claim compression or increased cryptographic strength.
- No plaintext original file may be released until FRA1E authentication and FRA1 SHA-256 verification both pass.
- Existing FRA1E compatibility vectors must remain unchanged.

### Task 1: FRA1-QR transport codec

**Files:**
- Create: `fra1qr.js`
- Create: `tests/fra1qr.test.js`

**Interfaces:**
- Consumes: arbitrary FRA1E bytes as `Uint8Array`.
- Produces:

  - `FRA1QR.reassemble(frameTexts) -> Uint8Array`

const assert = require('assert');
const Q = require('../fra1qr.js');

function bytes(n) {

const raw = Q.decodeFrameText(corrupted[2]);

corrupted[2] = Q.encodeFrameText(raw);

- [ ] **Step 3: Implement the minimal transport module**

Create `fra1qr.js` as a UMD-style module matching `codec.js`. Use this exact v0 binary frame layout:

```text
0..3    ASCII FQ10
4       version = 1
5..12   transfer ID, 8 bytes
13..14  frame index, uint16 BE, zero-based
15..16  frame count, uint16 BE
17..18  payload length, uint16 BE
19..22  total FRA1E length, uint32 BE
23..30  first 8 bytes of SHA-256(FRA1E)
31..34  CRC32 of header bytes 0..30 concatenated with payload
35..    payload
```

Implement:

```js
split(bytes,{payloadBytes=1350,transferId}={})
parseFrameText(text)
reassemble(frameTexts)
missingIndexes(frameTexts)
encodeFrameText(binaryFrame)
decodeFrameText(text)
crc32(bytes)
```

Rules:

```js
if (payloadBytes < 256 || payloadBytes > 1600) throw new Error('Dimensione chunk FRA1-QR non valida');
if (frameCount > 65535) throw new Error('Troppi frame FRA1-QR');
if (frame.transferId !== first.transferId) throw new Error('Frame di transfer diversi');
if (CRC mismatch) throw new Error('CRC FRA1-QR non valido');
if (missing indexes exist) throw new Error('Frame mancanti: ...');
if (reassembled length !== declared total) throw new Error('Lunghezza FRA1E ricostruita non valida');
```

Base64URL encoding must be ASCII-only and reversible without padding. In Node use `Buffer` when present; in browser fall back to `btoa`/`atob` over binary strings.

For SHA-256 prefix, make `split` asynchronous and use `crypto.subtle.digest` exactly as existing `codec.js` does. Update the test to use an async IIFE and `await Q.split(...)`.
